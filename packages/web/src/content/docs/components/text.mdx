# Text

`Text` displays styled text with colors, attributes, and selection. Use it for labels and prose. Use [Code](/docs/components/code) or [Markdown](/docs/components/markdown) for parsed rich content.

## Availability

| Field           | Availability         |
| --------------- | -------------------- |
| Package         | `@opentui/core`      |
| Core renderable | `TextRenderable`     |
| React           | `<text>` (automatic) |
| Solid           | `<text>` (automatic) |
| Status          | Built in             |

## Basic usage

### Renderable API

```typescript
import { TextRenderable, createCliRenderer } from "@opentui/core"

const renderer = await createCliRenderer()

const text = new TextRenderable(renderer, {
  id: "greeting",
  content: "Hello, OpenTUI!",
  fg: "#00FF00",
})

renderer.root.add(text)
```

## Text attributes

Combine text attributes with bitwise OR:

```typescript
import { TextRenderable, TextAttributes } from "@opentui/core"

const styledText = new TextRenderable(renderer, {
  id: "styled",
  content: "Important Message",
  fg: "#FFFF00",
  attributes: TextAttributes.BOLD | TextAttributes.UNDERLINE,
})
```

You can also apply bold, italic, and underline separately:

```text terminal=text-attributes
bold       Important message
italic     Additional context
underline  Documentation
```

### Available attributes

| Attribute                      | Description        |
| ------------------------------ | ------------------ |
| `TextAttributes.BOLD`          | Bold text          |
| `TextAttributes.DIM`           | Dimmed text        |
| `TextAttributes.ITALIC`        | Italic text        |
| `TextAttributes.UNDERLINE`     | Underlined text    |
| `TextAttributes.BLINK`         | Blinking text      |
| `TextAttributes.INVERSE`       | Inverted colors    |
| `TextAttributes.HIDDEN`        | Hidden text        |
| `TextAttributes.STRIKETHROUGH` | Strikethrough text |

## Template literals for rich text

Use the `t` template tag to style parts of one text element:

```typescript
import { TextRenderable, t, bold, underline, fg, bg, italic } from "@opentui/core"

const richText = new TextRenderable(renderer, {
  id: "rich",
  content: t`${bold("Important:")} ${fg("#FF0000")(underline("Warning!"))} Normal text`,
})
```

### Available style functions

```typescript
import { t, bold, dim, italic, underline, blink, reverse, strikethrough, fg, bg } from "@opentui/core"

// Basic attributes
t`${bold("bold text")}`
t`${italic("italic text")}`
t`${underline("underlined")}`
t`${strikethrough("deleted")}`

// Colors
t`${fg("#FF0000")("red text")}`
t`${bg("#0000FF")("blue background")}`

// Combining styles
t`${bold(fg("#FFFF00")("bold yellow"))}`
```

React and Solid can compose inline `<span>`, `<b>`, `<strong>`, `<i>`, `<em>`, `<u>`, `<br>`, and `<a href>` elements
inside `<text>`. They are text-only children. They cannot mount directly under a Box or another layout element. See
[inline text elements](/docs/components#inline-text-elements) for availability.

## Positioning

```typescript
const text = new TextRenderable(renderer, {
  id: "positioned",
  content: "Absolute position",
  position: "absolute",
  left: 10,
  top: 5,
})
```

## Align lines

`textAlign` pads each rendered line inside the text width. The pad for one line does not depend on the longest line.

```typescript
const text = new TextRenderable(renderer, {
  content: "hi\nworld",
  width: 10,
  height: 2,
  textAlign: "center",
})
```

```text terminal=text-align-lines
left        center      right
0123456789  0123456789  0123456789
hi              hi              hi
world         world          world
```

`"left"` is the default. `"center"` and `"right"` use leftover columns in the text width. A line that already fills the text width does not move.

Set a width, or let a parent stretch the text. Alignment has no effect when every line already fills the text width.

Wrapping runs first. Then `textAlign` pads each rendered line.

Change `textAlign` after mount with `text.textAlign = "right"`. `CodeRenderable` inherits the same option.

`textAlign` does not replace [Yoga box alignment](/docs/core-concepts/layout#alignment).

## Text selection

Text selection lets users copy text. It is on by default:

```typescript
const selectableText = new TextRenderable(renderer, {
  id: "selectable",
  content: "Select me!",
  selectable: true, // Default is true
})

const nonSelectable = new TextRenderable(renderer, {
  id: "label",
  content: "Button Label",
  selectable: false, // Disable selection
})
```

## Find the text under the pointer

Attach application data to a chunk with `metadata`. OpenTUI never reads it. A lookup returns the same value by
identity:

```typescript
import { StyledText, TextRenderable } from "@opentui/core"

const file = { path: "src/index.ts", line: 12 }
const output = new TextRenderable(renderer, {
  content: new StyledText([
    { __isChunk: true, text: "Error in " },
    { __isChunk: true, text: "src/index.ts:12", metadata: file },
  ]),
  onMouseDown(event) {
    const hit = this.getStyledTextHit(event.x - Math.trunc(this.screenX), event.y - Math.trunc(this.screenY))
    if (hit) openFile(hit.metadata as typeof file)
  },
})
```

`getStyledTextHit` takes whole cells. A renderable draws from its truncated screen position, so subtract
`Math.trunc(this.screenX)` and `Math.trunc(this.screenY)`. Subtracting a fractional position, for example after
`translateX = 0.5`, yields a fractional cell and no hit.

`TextNodeRenderable` accepts the same `metadata` option. Child nodes inherit it, as they inherit `link`.

Both lookups read the last frame the terminal has shown:

- `renderer.getTextMetadataAt(x, y)` takes screen cells and returns the metadata, or `undefined`.
- `getStyledTextHit(x, y)` on `TextRenderable`, `CodeRenderable`, and `TextTableRenderable` takes cells relative to
  the renderable. It returns `{ metadata }`, or `null`. The table version also returns `cell: { row, column }`.

A cell answers only while it shows a fragment of the current content. These cells return nothing:

- cells covered by another renderable, clipped by an `overflow: "hidden"` ancestor, or hidden;
- padding, borders, truncation ellipses, and empty space;
- cells of a frame that is still being written to the terminal, or that was skipped;
- cells of content that was replaced or destroyed, even while the old frame is still on screen;
- every cell after the terminal is suspended, cleared, or switched between the main and alternate screen, until the
  next frame is presented.

`getStyledTextHit` also checks the renderer's hit grid, so it returns `null` while `useMouse` is `false` or while
another renderable captures a drag. `getTextMetadataAt` does not depend on the hit grid.

`metadata` does not create a terminal hyperlink. A chunk can carry both `link` and `metadata`. A `TextareaRenderable`
placeholder chunk with `metadata` throws a `TypeError`.

When you use a `TextBuffer` directly, as `CodeRenderable` does internally, `metadata` is part of the chunk's style,
like `link`:

- Clearing a buffer's highlights, or covering a cell with a higher-priority highlight, removes the chunk's colors,
  link, and metadata from those cells.
- Metadata is not kept for a buffer whose `SyntaxStyle` is shared with other buffers. Its cells return nothing, so a
  lookup never returns another buffer's metadata. Give each buffer its own `SyntaxStyle` to keep metadata.

## Properties

| Property                         | Type                              | Default      | Description                              |
| -------------------------------- | --------------------------------- | ------------ | ---------------------------------------- |
| `content`                        | `string \| StyledText`            | `""`         | The text content to display              |
| `fg`                             | `string \| RGBA`                  | `#FFFFFF`    | Foreground (text) color                  |
| `bg`                             | `string \| RGBA`                  | transparent  | Background color                         |
| `attributes`                     | `TextAttributes`                  | `0`          | Text styling attributes                  |
| `selectable`                     | `boolean`                         | `true`       | Whether users can select the text        |
| `wrapMode`                       | `"none" \| "char" \| "word"`      | `"word"`     | Line wrapping mode                       |
| `textAlign`                      | `"left" \| "center" \| "right"`   | `"left"`     | Per-line alignment within the text width |
| `position`                       | `"relative" \| "absolute"`        | `"relative"` | Positioning mode                         |
| `left`, `top`, `right`, `bottom` | `number \| "auto" \| "{number}%"` | -            | Position offsets                         |

## Example: status bar

```typescript
import { TextRenderable, BoxRenderable, t, bold, fg } from "@opentui/core"

const statusBar = new BoxRenderable(renderer, {
  position: "absolute",
  bottom: 0,
  width: "100%",
  height: 1,
  backgroundColor: "#333333",
  flexDirection: "row",
  justifyContent: "space-between",
  paddingLeft: 1,
  paddingRight: 1,
})
statusBar.add(
  new TextRenderable(renderer, {
    content: t`${bold("myfile.ts")} - ${fg("#888888")("TypeScript")}`,
  }),
)
statusBar.add(
  new TextRenderable(renderer, {
    content: t`Ln ${fg("#00FF00")("42")}, Col ${fg("#00FF00")("15")}`,
  }),
)

renderer.root.add(statusBar)
```
