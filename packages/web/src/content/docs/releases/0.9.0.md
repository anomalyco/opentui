---
date: 2026-11-14
summary: Markdown runs on OpenTUI's native engine, which parses each streamed chunk once, and `renderBlock` replaces `renderNode`.
---

In 0.9.0, Markdown runs on OpenTUI's native engine, the same engine the Rust widget uses. In 0.8.3, `MarkdownRenderable` parsed with `marked` in JavaScript and lexed the open end of the document again on every chunk. In a growing list, the open end is the whole list, so streaming one list took 21,430 million instructions. `MarkdownRenderable` also sent all prose to the Tree-sitter worker for styling. The native engine reads each chunk once and writes paragraphs and headings into their text nodes itself. Streaming the same list now takes 5.9 million instructions. Over one streamed answer, JavaScript's styled-text writes for prose went from 1,595 to 0, and the prose characters sent to the highlighter went from 56,223 to 0.

Because the engine follows CommonMark 0.31.2 and GFM, some documents look different. While streaming, a line that can still change kind, such as a possible table row or a heading underline, waits for its end before it shows. A table appears when its delimiter row arrives, and task items show ☐ and ☑. The token tree is gone, so `renderNode(token, context)` becomes `renderBlock(block, context)`, and you switch on `block.kind` instead of `token.type`:

```ts
// 0.8.3
renderNode: (token) => {
  if (token.type !== "heading") return undefined
  return new TextRenderable(renderer, { content: token.text.toUpperCase() })
}
// 0.9.0
renderBlock: (block) => {
  if (block.kind !== "heading") return undefined
  return new TextRenderable(renderer, { content: block.text.toUpperCase() })
}
```

`internalBlockMode` is gone: every top-level block is its own renderable, one blank row apart. Code that read the parse state reads `blocks` and `committedBlockCount` instead, and the React and Solid prop is `renderBlock` too. The [Markdown](/docs/components/markdown) page has the full migration list.

The new `inlineHook` option replaces the private chunk callback that apps had to override to show IDs as titled links. That callback missed the streaming preview and table cells, so on a typical answer 9 of 18 frames showed the raw ID. The hook gets the spans of every paragraph, heading, and table cell and returns the spans to show. A span with a `target` in a paragraph or heading becomes clickable through `markdown.targetAt(x, y)`. `inlineHookFilter` runs the hook only on blocks that contain one of its strings, so other blocks stay on the native path:

```ts
const markdown = new MarkdownRenderable(renderer, {
  content,
  syntaxStyle,
  inlineHookFilter: ["ses_"],
  inlineHook: (spans) =>
    spans.map((span) => {
      const title = span.code ? titles.get(span.text) : undefined
      return title ? { ...span, text: title, target: span.text } : span
    }),
})
```

Input now has one stdin parser, the native one. 0.8 had two: the TypeScript parser was the default, and the native parser was opt-in through `experimental_nativeInput`. They did not always return the same keys for the same bytes. The TypeScript parser gave `ESC ,` no key name, dropped `CSI 1;2 R` instead of reporting Shift+F3, and read an SGR button-32 report as a move instead of a drag. Remove `experimental_nativeInput` and `stdinParserMaxBufferBytes` from your renderer config. To report a parser bug, attach an `OTUI_STDIN_LOG` capture. `parseKeypress()` keeps its signature but decodes with the native parser, so under Node it needs `--experimental-ffi`. You can feel one change: once a terminal confirms the Kitty keyboard protocol, Escape arrives at once instead of after a 20 ms wait.

The declarative composition layer is gone too: `h()`, `delegate()`, `vstyles`, and the construct factories such as `Box()` and `Text()`. Create renderables with their classes and add their children:

```ts
// 0.8.3
renderer.root.add(Box({ border: true }, Text({ content: "Done" })))
// 0.9.0
const box = new BoxRenderable(renderer, { border: true })
box.add(new TextRenderable(renderer, { content: "Done" }))
renderer.root.add(box)
```

Use the `t` template instead of `vstyles`, for example ``t`${bold("Done")}` ``, and the `renderAfter` option instead of `Generic()`. `Renderable.add()` now accepts only a `Renderable`, so narrow a nullable value before you add it.

React and Solid now handle a removed prop the same way. They used to map JSX props to renderables in separate code, and the two disagreed. In Solid, a key removed from `style` kept its old value, so `style={on ? { border: true } : {}}` left the border on screen. React wrote `null` for a removed prop, and `opacity = null` means 0, so removing `opacity` hid the box. Both reconcilers now call `setRenderableProp` in Core and write a removed prop as `undefined`, which restores the default. If your custom setter checks `value === null` to detect removal, make it accept `undefined` too.

Two new edit buffer methods convert between JavaScript string indexes and cell offsets. Edit buffer offsets count display cells, but JavaScript indexes a string in UTF-16 units, and the two diverge at the first tab or wide character. In `ab\tcd` with the default tab width of 2, `d` is at string index 4 but at cell offset 5, so a plugin that passed the string index deleted `c`. Neither method moves the cursor:

```ts
buffer.setText("ab\tcd")
const offset = buffer.stringIndexToCellOffset(buffer.getText().indexOf("d")) // 5
buffer.setCursorByOffset(offset)
buffer.cellOffsetToStringIndex(buffer.getCursorPosition().offset) // 4
```

The new `layoutMode: "list"` makes long columns cheaper to lay out. Before, a long column, such as a transcript, made Yoga run its flex pass over every row when one row changed. A list lays out its rows as a column and reuses the size of each row that did not change. Rows never grow or shrink; otherwise, a list lays out like a flex column with `overflow: "scroll"`. For ScrollBox content, set `contentOptions: { layoutMode: "list" }`. In a 1,000-row select, a frame that appends one row costs 1.54 million instructions in list mode. Before list mode reused row sizes, the same frame cost 22.39 million.

## Breaking changes

- **core:** `MarkdownRenderable` parses with the native engine, and `marked` is no longer a dependency. `renderBlock(block, context)` replaces `renderNode(token, context)`, also as a React and Solid prop. `blocks` and `committedBlockCount` replace `internalBlockMode` and the parse state. Paragraphs and headings are `TextRenderable`s, so code that set `onChunks` or `onHighlight` on them moves to `inlineHook`. The hook runs when the content or options change, also inside a setter, not when a highlight arrives. See [Markdown](/docs/components/markdown). ([#2079](https://github.com/anomalyco/opentui/pull/2079), [#2023](https://github.com/anomalyco/opentui/pull/2023))
- **core:** A `MarkdownCodeBlockRenderer` gets a `MarkdownCodeBlock` instead of `Tokens.Code`. Its `closed` field tells whether the closing fence has arrived. See [Markdown](/docs/components/markdown). ([#2079](https://github.com/anomalyco/opentui/pull/2079))
- **core:** The vnode composition API is removed: `h()`, `VNode`, `delegate()`, `instantiate()`, `Generic()`, `VRenderable`, `vstyles`, and the factories `Box()`, `Text()`, `Input()`, `Select()`, `TabSelect()`, `ASCIIFont()`, `FrameBuffer()`, `Code()`, and `ScrollBox()`. Create renderables with `new` and `add()`, use the `t` template instead of `vstyles`, and use the `renderAfter` option instead of `Generic()`. See [Renderables](/docs/core-concepts/renderables). ([#2000](https://github.com/anomalyco/opentui/pull/2000))
- **core:** `Renderable.add()` and `insertBefore()` accept only a `Renderable`, and `TextRenderable` accepts only text children. Narrow a nullable or `BaseRenderable` value before you add it. See [Renderables](/docs/core-concepts/renderables). ([#2000](https://github.com/anomalyco/opentui/pull/2000))
- **core:** Input always uses the native parser. The `experimental_nativeInput` and `stdinParserMaxBufferBytes` options, the `OTUI_NATIVE_INPUT_PARSER` and `OTUI_NATIVE_INPUT_SHADOW` variables, and `StdinParser` with its types are removed. Use `renderer.keyInput`, `prependInputHandler`, or `subscribeOsc` instead. This fixes the F3 bugs that @FasterPHP reported. See [Keyboard input](/docs/core-concepts/keyboard). ([#1981](https://github.com/anomalyco/opentui/pull/1981))
- **core:** `MouseParser` and `nonAlphanumericKeys` are removed. `parseKeypress()` decodes with the native parser, needs `--experimental-ffi` under Node, and returns `null` for empty input. Use renderable mouse events or `createMockMouse` instead of `MouseParser`, and `terminalNamedSingleStrokeKeys` instead of `nonAlphanumericKeys`. See [Keyboard input](/docs/core-concepts/keyboard). ([#2016](https://github.com/anomalyco/opentui/pull/2016))
- **core:** React and Solid write a removed prop or `style` key through the new `setRenderableProp` as `undefined`, not `null`, so the setter restores its default. A custom setter that checks `value === null` must also accept `undefined`. See [React bindings](/docs/bindings/react). ([#2018](https://github.com/anomalyco/opentui/pull/2018))
- **core:** `InputRenderableOptions` no longer has `onSubmit`, which `InputRenderable` never called. Listen for the `enter` event instead. Contributed by @posva. See [Input](/docs/components/input). ([#1216](https://github.com/anomalyco/opentui/pull/1216))
- **core:** `ExtmarksController.adjustExtmarksAfterDeletion()` is removed; the edit buffer now moves extmarks itself. For a malformed range, `create()` returns 0 instead of throwing an error. Because the buffer owns its extmarks, a controller's `destroy()` leaves them in place; call `clear()` to drop them. See [Editing buffers and views](/docs/extend/editing). ([#2104](https://github.com/anomalyco/opentui/pull/2104))
- **core:** Siblings with the same `zIndex` paint in child order instead of the order they were added. A renderable inserted or moved before a sibling paints below it, and where they overlap, the later sibling gets the click. This also applies to a Solid `<Show>` before an overlapping sibling. To keep a renderable on top, give it a higher `zIndex`. See [Renderables](/docs/core-concepts/renderables). ([#2119](https://github.com/anomalyco/opentui/pull/2119))
- **native:** You need Zig 0.17.1 to build the native library and the Zig module. This version fixes an LLVM miscompile of casts from signed to narrower unsigned values. See [Zig](/docs/native/zig). ([#2045](https://github.com/anomalyco/opentui/pull/2045))
- **native:** In the Zig module, `yoga.yogaNodeGetContentBoxChecked(node, &box)` is now `yoga.yogaNodeGetLayoutChecked(node, &layout, &box)`. `yoga_c.otYogaNodeGetComputedLayout` takes a third argument, `null` or a four-float content box. See [Zig](/docs/native/zig). ([#2090](https://github.com/anomalyco/opentui/pull/2090))
- **native:** `opentui.h` has new calls and types, but `OT_CONTEXT_ABI_VERSION` stays 2. Build a C or Rust host with the header, bindings, and library from the same release. `opentui-sys` fails its build when the library's header differs from its bindings. See [C](/docs/native/c). ([#1949](https://github.com/anomalyco/opentui/pull/1949), [#2049](https://github.com/anomalyco/opentui/pull/2049), [#2104](https://github.com/anomalyco/opentui/pull/2104))
- **rust:** The experimental crates `opentui-sys`, `opentui`, and `opentui-ssh` moved into the OpenTUI repository and are not published, so depend on them by Git revision. On Linux and macOS they link the static library by default; for the shared library, turn off default features in every crate that depends on them. On Windows, ship `opentui.dll` beside the app. See [Rust](/docs/bindings/rust). ([#1946](https://github.com/anomalyco/opentui/pull/1946), [#1949](https://github.com/anomalyco/opentui/pull/1949), [#1984](https://github.com/anomalyco/opentui/pull/1984), [#1992](https://github.com/anomalyco/opentui/pull/1992))
- **rust:** `Markdown` parses with the native engine and follows CommonMark and GFM, so rules and setext headings can render differently. Its code fences now wrap by word; a standalone `Code` still does not wrap. `Input::max_length` counts UTF-16 units, as Core does. See [Rust](/docs/bindings/rust). ([#2049](https://github.com/anomalyco/opentui/pull/2049), [#2089](https://github.com/anomalyco/opentui/pull/2089), [#2017](https://github.com/anomalyco/opentui/pull/2017))
- **rust:** An app's priority-0 highlight paints under syntax colors. Textareas that share one style table share one syntax theme: the one set last on any of them. After `clear_highlights`, a theme change brings syntax colors back only at the next edit. See [Rust](/docs/bindings/rust). ([#2026](https://github.com/anomalyco/opentui/pull/2026), [#2030](https://github.com/anomalyco/opentui/pull/2030))
- **rust:** On Unix, Ctrl+Z stops the app's whole process group, and a suspend or release drops the rest of the input from that read. On Windows, `Host::release` hands the terminal to its task as on Unix. `ScrollbackSurface::commit_rows` fails after a change of width or width method until the surface renders again. See [Rust](/docs/bindings/rust). ([#1950](https://github.com/anomalyco/opentui/pull/1950), [#1958](https://github.com/anomalyco/opentui/pull/1958), [#2043](https://github.com/anomalyco/opentui/pull/2043), [#2082](https://github.com/anomalyco/opentui/pull/2082))

## Changed

- **core:** Markdown follows CommonMark 0.31.2 and GFM. While streaming, a line that can still change kind waits for its end, and a table shows when its delimiter row arrives. Task items show ☐ and ☑. See [Markdown](/docs/components/markdown). ([#2079](https://github.com/anomalyco/opentui/pull/2079), [#2078](https://github.com/anomalyco/opentui/pull/2078))
- **core:** Each top-level Markdown block is its own renderable, one blank row apart, so apps on the old `"coalesced"` default now see blank rows between some blocks. Set `tableOptions.style: "columns"` to get the old top-level table style. See [Markdown](/docs/components/markdown). ([#2079](https://github.com/anomalyco/opentui/pull/2079))
- **core:** The default Markdown style strikes through `~~text~~` unless the theme sets `strikethrough: false`. See [Markdown](/docs/components/markdown). ([#2027](https://github.com/anomalyco/opentui/pull/2027))
- **core:** A streaming code fence in Markdown sends only its new text to the Tree-sitter worker. New text shows plain until its highlight arrives, and `getLineHighlights()` on a streaming fence returns no syntax records. `MockTreeSitterClient` in `@opentui/core/testing` has `highlightAppend()`. See [Syntax highlighting with Tree-sitter](/docs/reference/tree-sitter). ([#2102](https://github.com/anomalyco/opentui/pull/2102))
- **core:** Extmarks live in the native edit buffer. Undo and redo restore them, IDs are never reused, queries return extmarks in (start, id) order, and an edit that changes part of a virtual extmark drops it. Extmarks no longer clear the buffer's other highlights on each edit. See [Editing buffers and views](/docs/extend/editing). ([#2104](https://github.com/anomalyco/opentui/pull/2104), [#2094](https://github.com/anomalyco/opentui/pull/2094))
- **core:** When a terminal confirms the Kitty keyboard protocol, Escape arrives at once instead of after 20 ms. Kitty, Ghostty, foot, and Alacritty confirm it, but WezTerm by default and tmux do not. See [Keyboard input](/docs/core-concepts/keyboard). ([#1948](https://github.com/anomalyco/opentui/pull/1948), [#1971](https://github.com/anomalyco/opentui/pull/1971))
- **core:** Theme and palette queries end at the DA1 reply instead of on timers. `waitForThemeMode()` resolves with `null` when no OSC 11 reply arrives, and `getPalette()` reports the default colors of a terminal that does not answer OSC 4. See [Terminal capabilities](/docs/reference/terminal-capabilities). ([#1969](https://github.com/anomalyco/opentui/pull/1969))
- **core:** In split-footer mode, a frame writes up to 64 captured stdout rows instead of 8, so output at 2,000 rows per second no longer falls behind. `writeToScrollback` commits stay at 8 per frame. See [Renderer](/docs/core-concepts/renderer). ([#2084](https://github.com/anomalyco/opentui/pull/2084))
- **three:** Writing `ThreeRenderable.aspectRatio` sets the Yoga layout ratio, which `getAspectRatio()` returns; reading it still returns the display ratio. An `aspectRatio` passed at construction no longer throws. See [Three.js WebGPU](/docs/reference/three). ([#2101](https://github.com/anomalyco/opentui/pull/2101))
- **native:** Inside GNU screen, OpenTUI ignores `COLORTERM` and `WT_SESSION` and writes 256-color SGR, because screen drops 24-bit colors by default. Set `OPENTUI_FORCE_TRUECOLOR=1` when screen's `truecolor` setting is on. See [Terminal capabilities](/docs/reference/terminal-capabilities). ([#1967](https://github.com/anomalyco/opentui/pull/1967), [#1982](https://github.com/anomalyco/opentui/pull/1982))
- **native:** `WT_SESSION` enables OSC 8 hyperlinks on every host OS when `TERM` is unset, empty, or starts with `xterm` and no multiplexer is present. So a Windows Terminal client gets clickable links from a Linux or macOS host when a remote session forwards `WT_SESSION`. See [Terminal capabilities](/docs/reference/terminal-capabilities). ([#1976](https://github.com/anomalyco/opentui/pull/1976))
- **native:** Notifications in tmux and GNU screen use the same passthrough as OSC 52. Inside screen, each non-ASCII character in OSC 777 and OSC 9 text becomes a space. See [Notifications](/docs/core-concepts/notifications). ([#2021](https://github.com/anomalyco/opentui/pull/2021))
- **native:** Each Linux `libopentui.a` includes a private libc++ and libc++abi. A static link needs no system libc++ and also works on musl. See [C](/docs/native/c). ([#1991](https://github.com/anomalyco/opentui/pull/1991))
- **native:** When two highlight ranges with the same priority cover a cell, the later range wins. Before, the winner depended on hash-map order. See [Editing buffers and views](/docs/extend/editing). ([#2025](https://github.com/anomalyco/opentui/pull/2025))
- **native:** Layout does less work per frame. Rounding visits only the subtrees that a solve laid out, a larger height cap counts as a cache hit, and Linux builds call Yoga's inline helpers directly. A status glyph beside 10,000 rows costs 30.6% fewer instructions per frame. See [Rendering pipeline](/docs/core-concepts/rendering-pipeline). ## Security

- **native:** An OSC 8 link target must be non-empty UTF-8 of at most 512 bytes with no control characters. Before, an ESC or BEL in a link target ended the sequence, and the terminal ran the rest as commands. Reported by @carsteneu, who also wrote the first fix. See [Terminal capabilities](/docs/reference/terminal-capabilities). ([#1996](https://github.com/anomalyco/opentui/pull/1996))
- **native:** Notification text must be UTF-8, and C0, DEL, and C1 characters become spaces. OSC 9 text that starts with a digit gets a leading space, and `triggerNotification()` returns `false` in ConEmu. See [Notifications](/docs/core-concepts/notifications). ([#1998](https://github.com/anomalyco/opentui/pull/1998))
